# Local product walkthrough

Start with the [root README quickstart](../README.md#run-locally), or use the [Docker Compose recipe](deployment.md#docker-compose). The default addresses are `http://127.0.0.1:3000` for the app and `http://127.0.0.1:8000` for the API. No provider account is needed: the local app retrieves stored passages and quotes their text without a language model.

The public corpus (the stored collection searched by the app) contains three California residential landlord–tenant statutory sections. Their capture dates do not establish when each provision was legally effective. Use the fictional [sample lease](../samples/example-lease.txt) for document review.

1. Open **Home**. Its two choices lead to **Research** or **My documents**. **Developer tools** expands to **Evaluation lab** and **Project reference**. [Home screenshot](../artifacts/browser/home-desktop.png).
2. In **Research**, choose the deposit-paperwork example or enter an in-scope question. The answer starts with an exact source extract, followed by supporting passages and limits. Select a numbered citation to focus the passage from that source version. Expand source and run details to inspect identifiers, retrieval settings and citation checks. These checks confirm that the quote belongs to the cited passage; they do not independently assess its legal meaning. [Research screenshot](../artifacts/browser/research-desktop.png).
3. Try another jurisdiction, an unsupported historical date, a federal patent question or a request to decide whether your landlord broke the law. These should explain the evidence gap and abstain (decline to answer from insufficient support). If the local API is disconnected, the app instead reports a connection failure and offers retry.
4. Open **My documents** and upload `samples/example-lease.txt`, a synthetic lease with fictional parties and a deliberately questionable fixed cleaning clause. Wait for **Ready**, inspect its extracted section, then run analysis. Literal document text, rule-based considerations and public authorities have separate labels. A consideration does not determine whether a clause is unlawful. Real parsing also accepts PDF, DOCX, UTF-8 text and Markdown: the upload limit is 10 MB, with additional page, expanded-size, text and timeout caps. Scanned PDFs require optical character recognition (OCR), which is unavailable. [Documents screenshot](../artifacts/browser/documents-desktop.png).
5. Ask what cleaning fee the document states, follow its private citation, and inspect the public-source comparison. Download the original or replace it with another synthetic file. A ready replacement removes the previous version from search. Replacement and deletion purge private questions, answers and analyses, and conservatively remove **all saved custom research/search history in the workspace**, including questions using public sources. Confirming deletion immediately revokes document access. Frozen public evaluation reports remain. The app reports pending file cleanup separately from completed deletion; see the [retention limits](security.md#stored-data).
6. Under **Developer tools → Evaluation lab**, run the frozen starter benchmark (a fixed set of labeled questions) with four configurations. Inspect measured retrieval scores, latency, zero provider usage, failure cases and the reproducibility manifest, which records the inputs and settings needed to repeat a run. The local hash-vector method converts text into numeric vectors deterministically; it is not trained semantic retrieval or Pinecone. Its failure to meet the starter recall threshold is retained in the report. Independent assessment of answer meaning and support remains unperformed. [Evaluation screenshot](../artifacts/browser/evaluations-desktop.png).
7. Open **Developer tools → Project reference** for corpus versions, API guidance, architecture and deferred validation. From the repository root, reproduce the comparison with `uv run python -m evaluations run --output .local/evaluations/local-run.json`, or try the [Python/TypeScript clients](../examples/). The ignored output location preserves the committed evidence.

The browser keeps its workspace session in an HttpOnly cookie, which browser JavaScript cannot read. This is a local demo identity mechanism, without production single sign-on (SSO) or account recovery. If the session expires, reconnecting creates a new workspace; previous documents do not transfer. Session expiry itself does not delete stored documents.

## Verification and limits

The [stored browser report](../artifacts/browser/report.json) records real local browser/API interactions, including failure/cancellation, source focus, modal keyboard handling, replacement/deletion, nine foreign-session denial checks and responsive layouts. The [stored container smoke report](../artifacts/container-smoke.json) separately exercises PostgreSQL and the production Next.js/API stack. These are historical verification artifacts using synthetic private input; their screenshots and reports contain no session credentials. See the [verification record](verification.md) for the recorded checks and their limits.

Automated checks do not establish novice-user comprehension, a complete accessibility audit or independent legal quality. Live Pinecone/model execution, human-reviewed answer labels, public HTTPS/production identity and a participant study remain unexecuted validation steps. See [design](design.md), [security](security.md) and [deployment](deployment.md).
