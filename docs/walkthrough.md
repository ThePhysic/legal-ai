# Local product walkthrough

Start the native or Docker stack using the README. Everything below uses the offline local implementation and synthetic sample; no provider account is needed. The three captured California statutory sections are a narrow research corpus, with unknown legal effective-date intervals.

1. Open Home. The two choices lead directly to research or document review. Developer evaluation and project reference sit under **Developer tools**. [Home screenshot](../artifacts/browser/home-desktop.png).
2. Choose the deposit-paperwork example or enter a new in-scope question. The answer starts with a bounded source extract, followed by the full retrieved claims, limits and inspectable evidence. It does not claim a synthesized or professionally reviewed legal conclusion. Select a numbered citation to focus its exact versioned passage. Expand source and run details to inspect identifiers, retrieval configuration and identity checks. [Research screenshot](../artifacts/browser/research-desktop.png).
3. Try another jurisdiction, an unsupported historical date, a federal patent question or a request to decide whether your landlord broke the law. These should produce an evidence gap and abstention. A disconnected local API produces a separate connection failure with retry; it does not masquerade as insufficient legal evidence.
4. Open **My documents** and upload `samples/example-lease.txt`. This is a synthetic lease with fictional parties and a deliberately questionable fixed cleaning clause. Wait for Ready, inspect its extracted section, then run analysis. Literal document text, rule-based considerations and public authorities have separate labels. A consideration is not a determination that a clause is unlawful. [Documents screenshot](../artifacts/browser/documents-desktop.png).
5. Ask what cleaning fee the document states, and follow the citation into the private section. Inspect the public-source comparison. Download the original, replace it with another synthetic file, or confirm deletion. Replacement removes the previous current version from search; deletion revokes visibility and purges retained private answer/analysis content. Losing the local session cannot recover another workspace.
6. Under **Developer tools**, open **Evaluation lab** and run the frozen starter with four configurations. Inspect measured retrieval scores, latency, actual zero provider usage, failure cases and the reproducibility manifest. The deterministic hash-vector baseline fails the starter recall threshold; this is retained, not described as Pinecone or trained semantic retrieval. Citation identity is mechanical; independent semantic correctness/support remain unassessed. [Evaluation screenshot](../artifacts/browser/evaluations-desktop.png).
7. Open **Project reference** for actual corpus versions, API guidance, architecture and deferred gates. Reproduce the stored comparison with `uv run python -m evaluations run --output evaluations/reports/local-run.json`, or use the Python/TypeScript clients in `examples/`.

## Verification and limits

The committed browser report records real local HTTP/CDP interactions, including failure/cancellation, source focus, modal keyboard handling, replacement/deletion, nine foreign-session denial checks and responsive layouts. The container smoke report separately exercises PostgreSQL and the production Next.js/API stack. Both use synthetic private input; their screenshots and reports contain no session credentials.

Automated checks do not establish novice-user comprehension, a complete accessibility audit or independent legal quality. Real Pinecone/model execution, human-reviewed semantic labels, public HTTPS/production identity and a participant study remain explicit external validation gates. See [design](design.md), [security](security.md) and [deployment](deployment.md).
